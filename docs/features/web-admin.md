# 订阅页与管理后台

网站在 `apps/web`（Next.js），和流水线共用同一个数据库。本机运行 `pnpm dev`（开发）或由 launchd 常驻（上线），见 [上线部署](../maintenance/deployment.md)。

## 订阅页（`/`）

- 订阅者自己选主题和阅读语言（中文 / 原文），提交后收到确认邮件，点确认才开始收。
- 每个主题卡片显示博主头像（从左到右叠放）和 ID，超过 `subscribe_page.max_avatars`（默认 7）个只显示 +N。头像和显示名来自采集时记录的账号资料，还没采集过的账号显示首字母。
- **已订阅的邮箱直接在订阅页改设置**：用同一个邮箱重新选择主题和语言后提交，立即覆盖原设置，不需要确认邮件或管理链接。
  同时给该邮箱发一封"订阅设置已更新"通知（含修改前后的设置和改回去的链接，10 分钟内最多一封），防止被他人代改而不知情。
  不想允许直接覆盖时，把 `config/digest.yaml` 的 `subscribe_page.overwrite_existing` 设为 `false`。
- 新邮箱、已退订或未确认的邮箱仍需点确认邮件，避免给别人订阅。
- **邮件预览**：页面右侧展示一份固定的真实示例（`apps/web/data/preview.json`），由 `pnpm preview:snapshot` 从最近 7 天通过精选的推文里按评分取 `total_items` 条生成，
  之后不随每天的数据变化；想换一批时再运行一次（可加 `--days 14 --count 8`）。
- 每个主题有 RSS 地址，见 [邮件与 RSS](email.md#rss)。

其他页面：`/confirm/<token>` 确认订阅、`/preferences/<token>` 改主题和语言、`/unsubscribe/<token>` 退订、`/manage` 输入邮箱获取专属管理链接（合并发送的邮件页脚用它）。

## 管理后台（`/admin`）

在 `.env` 设置 `ADMIN_PASSWORD` 后开放，输入密码登录（8 小时有效）。没设置时这些页面不开放（404），也不会被搜索引擎收录。
打开 `/admin` 直接进反馈页；顶部导航有"订阅者 / 推送历史 / 读者反馈 / 账号"，右上角是"今日反馈"。

### 订阅者管理（`/admin/subscribers`）

列出每位订阅者的邮箱、状态（正常 / 待确认 / 已退订）、语言、主题、订阅和确认时间、最近发送日期和累计封数，
标出"主题全部失效""超过 3 天未确认"等问题；可按状态筛选、导出 CSV。

命令行：`pnpm subscribers` 列出同样的信息，加 `--csv` 导出到 `data/out/subscribers.csv`。

### 推送历史与重新推送（`/admin/deliveries`）

按天列出每一期的成功、失败、未收到人数和推文数。点开某一期（`/admin/deliveries/<日期>`）可以看到：

- 收件人：每人的结果、发送时间、收到几条、发送了几次；"已发出的"打开当时发出的全部条目（几封合在一页），"预览重发"打开现在重发会发出的条目（顶部注明分几封、去掉几条）；
- 发出的推文：每条被多少人收到；
- 发送记录：每一次定时发送、补发、重新发送、重试的时间和结果（合并发送会注明几人一封）。

重新推送（点按钮后需要再确认一次）：

- **重新发送**：给某一位重发这一期，按这一期**最新的内容**（含之后补采、重新评审的）和他现在的主题、语言重新挑选，生成一封带个人链接的邮件；
- **重试失败的**：这一期所有发送失败的人逐个重发；
- **补发给未收到的**：这一期结束前已确认、却没有任何发送记录的人（不会给之后才订阅的人补发旧内容）。

命令行：`pnpm resend` 列出推送历史；`pnpm resend --date 2026-10-19` 查看某一期；加 `--failed` 重试失败的、`--missing` 补发、`--to 邮箱` 重新发给某人。

每次发送都记在 `delivery_attempts` 表里（只增不改）；`deliveries` 保留每人每期的最终结果，重发失败不会覆盖之前已经成功的记录。

### 反馈（赞 / 踩）

反馈只在后台的邮件预览里做，发给读者的邮件里没有反馈链接。

- **每天的入口**：右上角"今日反馈"（`/admin/feedback/today`），直接打开最近一期发给管理员的完整邮件
  （`.env` 的 `ADMIN_EMAIL` 对应的订阅者；不是订阅者时用收到条目最多的那位）。
- **补之前的**：`/admin/feedback` 的"按期反馈"列出最近 14 期的赞 / 踩数；也可以从推送详情里任意一位的"已发出的"或"预览重发"进入。
- **怎么点**：预览里每条卡片底部最左边有灰色的赞 / 踩图标（`apps/web/public/icons/`）。点一下立即记录，不跳转、不确认；
  选中的赞变绿、踩变红，再点一次同一个取消，点另一个就改成另一个。
- **踩的原因**：踩了之后出现原因（话题不感兴趣 / 不喜欢这个作者 / 内容太浅 / 像广告或推广 / 重复 / 其他，可不选）和一个说明框，
  选原因或点"保存"（回车）即更新，随后自动收起成一行"原因：说明　修改"；点面板外面或按 Esc 也会收起。赞不需要原因。
- 每条推文只留一条后台评价（`feedback` 表 `source = admin`），重新打开预览会显示之前的评价、原因和说明。

反馈不直接参与选稿，机制见 [AI 精选](curation.md#5-人工反馈不过滤内容)，定期操作见 [日常运维](../maintenance/operations.md#根据反馈调整精选)。命令行：`pnpm feedback`（`--down` 只看踩，`--summary` 汇总）。

### 账号管理（`/admin/accounts`）

一张表看全部采集账号的质量，并在页面上增删账号、调权重。分档、建议移出和权重的规则见 [账号内容质量管理](accounts.md#账号内容质量管理)，和 `pnpm accounts` 用同一套算法。

- **质量表**：每个账号的主题、档位（优质 / 普通 / 样本不足 / 低质 / 不活跃，长期低质的标 ⚠）、近 14 天评审数、保留数、保留率、平均分、最近发推和上次采集日期、后台累计的赞 / 踩数、当前权重。
  默认按档位、保留率排序；可以按档位（含"⚠ 建议移出""调过权重"）和主题筛选。
- **新增账号**：填账号（`@name`、`name` 或主页链接都行）、选主题，点"添加账号"，写到 `config/topics.yaml` 那个主题的 `accounts` 末尾，下次生成采集清单时开始采集。
  同一账号可以再加到别的主题；已在这个主题里的会提示。账号存不存在不在这里检查，不存在时采集会跳过并提醒。
- **移出账号**：每行的"移出"，再确认一次，从所有主题里删掉这一行；账号在多个主题里时，主题标签上的 × 只从那一个主题移出。主题只剩一个账号时不能再移出。
  已采集的推文和账号资料不删，以后再加回来会接着用。
- **同步 X 关注**：点"立即同步"把自己 X 账号的关注列表里新的账号加进「我的关注」主题，显示上次同步的结果和已经取关的账号，机制见 [同步 X 关注](accounts.md#同步-x-关注)。
  同步在后台运行，几分钟后刷新页面看结果，输出在 `data/logs/follow-sync.log`。
- **调权重**：点权重（如 ×1）展开，填 0–2（留空 = 默认 1）和原因，保存后写到 `config/digest.yaml` 的 `account_weight`，原因写成那一行的行尾注释；留空或填 1 会删掉这一行。

改动只改涉及的那一行，文件里其他注释和对齐不变；改完先校验，不合法不会保存。网站发现配置文件变了会自动重新读取，订阅页的主题头像也随之更新，流水线和采集下次运行生效。
后台改的文件在 Mac mini 的 git 里显示为本地修改，拉取代码前先提交或 `git stash`，见 [日常运维](../maintenance/operations.md#账号维护)。
