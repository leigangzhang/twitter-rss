# 精选晨报 · 宣传设计说明

## 一句话

把公众号文章里的核心判断压缩成一组视觉：

> **几百条 X 推文，经 AI 精选，变成每天 30–60 条，同时进邮件和 RSS。**

## 叙事映射

| 公众号文章重点 | 视觉落点 |
|---|---|
| 每天几百条，真正值得读的只有几十条 | Hero 第一段 / 封面卡片 |
| 8 步过滤漏斗：采集、规则粗筛、AI 初审、编辑终审、人工反馈 | Hero 第二段 / 系统卡片 |
| `curation.md` 把“什么值得读”显式化；AI 照标准筛，人改标准 | 系统卡片主标题与漏斗 |
| 账号分档、权重和后台赞踩让标准持续修正 | 系统卡片的“人工反馈”层 |
| 最终每天 30–60 条，按评分排序 | Hero 第三段 / 分发卡片 |
| 一处采集，多处分发：邮件 + RSS | Hero 第四段 / 分发卡片 |
| 运行成本低；“每天不到 1 元”是文章口径 | 分发卡片第三个数据块与脚注 |
| 可以订阅，也可以自己部署 | 分发卡片 CTA |

## Hero 分镜

规格：1920×1080，5.0 秒，30fps，静音，无缝循环。

| 时间 | 画面 |
|---|---|
| 0.0–1.0s | 米白编辑网格；X 时间线里的卡片碎片散开；主标题「每天几百条，值得读的只有几十条。」 |
| 1.0–2.9s | 碎片被吸入五层漏斗：采集 → 规则粗筛 → AI 初审 3/5 分以上 → 编辑终审 → 人工反馈。虚线从“人工反馈”回到“AI 初审”。 |
| 2.6–3.9s | 输出「30–60 条 / 天」「5 个主题」「中文 / 原文」「邮件 + RSS」；收束句「不是爬虫，是一套精选系统。」 |
| 3.5–5.0s | 左侧真实邮件卡片叠放图，右侧「同一份精选，邮件和 RSS 都能读」；落版 GitHub 地址。首尾留出空白品牌帧，保证循环不跳。 |

### Card 02｜精选系统

```text
不是爬虫，
是一套精选系统

05 人工反馈    赞 / 踩 → 修正 curation.md

把“什么值得读”写成标准。
CURATION.MD · 6 CONTENT TYPES · 5-POINT SCORE
```

## 视觉系统

- 背景：`#F7F8FA`（米白）
- 主文字：`#15171A`（墨黑）
- 正文：`#2B2F36`
- 辅助文字：`#5F6670`
- 分隔线：`#DEE3E8`
- 品牌蓝：`#1F5FD6`
- 深蓝：`#16479F`
- 浅蓝底：`#F3F7FE`
- 主题强调色：`#B45309` / `#C2410C` / `#BE123C` / `#0369A1`
- 中文字体：Noto Sans SC（OFL）；数字/标签/URL：JetBrains Mono（OFL）。
- 版式：72px 外边距；细网格、细线、编辑排版；卡片使用统一的 1080×1440 画板。
- 图形母题：漏斗、邮件窗口、主题色小方块、RSS 波纹；不使用通用渐变球、3D、霓虹或“AI 大脑”图库图。

## 事实与边界

- **不写“100 位博主”**：公众号文章使用 100 位口径，但当前仓库 `config/topics.yaml` 只有 74 个账号槽位。Demo 保留文章的主叙事“几百条 → 30–60 条”，不把 100 作为主视觉。
- **“每天不到 1 元”只作为文章口径引用**：以脚注说明成本随 DeepSeek 用量和价格变化，不写成固定报价。
- **没有公开订阅地址**：CTA 只指向 GitHub，不写“立即订阅”或“永久免费”。
- **不写“所有邮箱都支持主题标签页”**：只写邮件和 RSS 双通道。
- **不写“官方 X 合作”**：文字标识只代表项目名，不代表 X 官方。
- 不使用 AIGC 生成图；邮件卡片和订阅页素材来自用户自己的公众号文章与项目页面，其他图形均为 HTML/CSS/SVG 原生绘制。
- 不展示订阅者邮箱、后台数据、API Key 或 `.env`。
